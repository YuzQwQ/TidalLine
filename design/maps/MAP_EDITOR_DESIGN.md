**几个实现上的取舍**

1. **旋转视图下实体照常画贴图**（2026-10-29 修订，原先是画字母/圆点标记）。
   做法不是"把贴图整体转 90°"——那样烘焙的左上光照会跟着转错；而是**屏幕朝向 = 实体朝向 + 视角**，
   90°/270° 取 `_side`、180° 取 `_back`。因为屏幕占格本身也在 90°/270° 宽高互换，选出来的变体
   与占格永远对得上，等于用现成的三向美术换了个看法，没有一张图是硬转的。
   代价：没有 `_side`/`_back` 变体的资源（少量结构件）转视角后仍是正面图，靠 `map-art-map.js` 登记兜底。
2. **静态层烘一次**。4032 格地块 + 132 个叠加 + 32 扇门画进离屏画布，只有旋转变化才重建；
   缩放只是把这张 32px 基准图按比例贴出去（关掉平滑，整数倍缩放时像素是硬的）。
3. **校验在浏览器里真跑**，不是假状态条。`map-validator.js` 无 `fs`、无 `assert`，直接 `<script>` 引入即可，
   和 node 侧同一份代码——这是 M0 拆 UMD 的直接回报。
4. **美术映射收进 shared**。`resolvePropArt` / `resolveOverlays` 原本只写在 `build-linhai-map.js` 里，
   M1 要在浏览器里画同样的图，只能二选一：复制一份，或者搬进 shared。搬完之后
   **编译输出逐字节不变**（props 40、overlays 132、doors 32 全等），说明这次重构没有副作用。
5. **`[hidden]` 被类选择器压过**。`.drop{display:grid}` 会让 `hidden` 属性失效，遮挡层一直盖在画布上，
   整张图看起来"发白"。加 `[hidden]{display:none!important}` 解决——这类 bug 只在截图里看得出来。

- 四个视角的坐标往返一致：`(10,10)` 在 0/90/180/270 下经投影→反投影都回到 `(10,10)`。
- 旋转后布局与 `figures/overview.png` 一致：运河 x30–35、北桥 y12–15、南桥 y40–42、

## 零点七、M2 已完成（2026-10-29）

编辑器现在能改图了。判据是 `index.html?selftest=1` 的 44 项断言全过——它们走的是真实事件路径
（`pointerdown/move/up` + `keydown`），不是直接调函数，验的正是"鼠标 → 工具 → 数据"这一段接线。

**这一版能做什么**

| 能力 | 说明 |
| --- | --- |
| 五种工具 | 选择 `1` / 画笔 `2` / 矩形 `3` / 油漆桶 `4` / 橡皮 `5` |
| 地形编辑 | 左栏点地形字符即拿起材质，按住拖动连续刷；矩形拖出即填；油漆桶四邻域整片换 |
| 实体放置 | 点容器 / 装饰 / 敌人条目即拿起，点画布放置；放完自动选中，id / 分区 / 偏好自动填 |
| 选择移动 | 选择工具点实体选中，拖动移动、方向键微调、Delete 删除；点空白处拖动平移 |
| 检查器 | 容器改类型与偏好；装饰改类型 / 名称 / 朝向 / 占地；敌人改类型与巡逻半径；出生撤离点改名与风险 |
| 撤销重做 | `Ctrl+Z` / `Ctrl+Shift+Z`，80 步上限；一次拖拽 = 一步，一次放置 = 一步 |
| 保存 | `Ctrl+S` 直接写回 layout.json（FSA）；不支持或被拦时自动降级为下载 |
| 自动草稿 | 编辑后 0.9 秒写 localStorage，重开页面时提示恢复 |
| 实时校验 | 每次改动 140ms 后重跑 18 条规则；点校验条目跳到出问题的格子 |

**四个设计决定**

1. **材质在调色板里，工具只决定"怎么用"。** 画笔配地形就是刷，配容器就是放。
   这样"放置"不需要第六个工具，也不会出现"选了容器却在用刷子"的矛盾状态。
2. **撤销粒度 = 一次手势。** `history.begin()` 在按下时拍快照，`end()` 在松手时比对差异才入栈。
   拖过两百格和点一格都是同一步。放置这类"可能失败"的动作用 `history.apply()`：
   函数返回操作结果，没有差异就不入栈，不会留下空气撤销步。
3. **配额不自动跟随。** 放一个容器会让 `quotas.containers` 与实际不符，校验立刻报 G11。
   这是刻意留的：配额是"想画成什么样"的声明，自动同步就退化成"已经画成什么样"的复印件。
   工具栏给了「同步配额」按钮，按了才改，并且本身是一步可撤销的操作。
4. **删除不清空选中。** 删完按 `Ctrl+Z`，实体回来、选中也回来，检查器能接着用。
   选中状态存的是 id 不是引用，因为撤销会整份替换 data。

**自测覆盖**

| 组 | 断言 |
| --- | --- |
| 载入 | 48 容器、0 错误、初始未标脏 |
| 材质 | 点条目拿起地形、自动切到画笔 |
| 画笔 | 刷成墙、标脏、撤销、重做 |
| 拖拽 | 连续刷两格、两格只占一步撤销 |
| 矩形 | 拖动有预览、松手六格填满、一步撤销干净 |
| 油漆桶 | 改动生效、一步撤销干净 |
| 放置 | 容器 +1、自动分区 / 偏好、自动选中、检查器出现 |
| 移动 | 拖动到右邻格、拖回、两步撤销、重做、方向键 |
| 删除 | Delete 生效、撤销回来、重做再删 |
| 敌人 | 放置 +1、撤销 |
| 橡皮 | 墙刷回地板、可撤销 |
| 序列化 | 不含 routes、幂等、字段数不变 |
| 配额 | 同步改回实际值、可撤销 |
| 收尾 | 全部撤销后与初始图逐字节一致 |

**踩到的三个坑**

- `setPointerCapture` 对合成事件会抛 `NotFoundError`，把整个 pointerdown 打断。包 try/catch。
- 自测里 `const placed = containers[last]` 拿到的是活引用，移动之后 `placed.x` 也跟着变了，
  `moved.x === placed.x + 1` 永远为假——断言要先把坐标取成数字。
- 画笔状态下按住拖动是"连续放"，不是"拖动"。移动必须先切到选择工具；
  这条反过来也说明工具语义是清楚的：画笔就是放，选择才是挪。

**能做什么**

| 能力 | 说明 |
| --- | --- |

**三个决定**

- **新图的 `quotas` 是 `null`，不是 `0`。** 写 `0` 的话，放下第一个箱子就报 G11"容器配额 0，实际 1"，
  新图一开工就红一片。`null` 表示"还没声明"，等你点"同步配额"才变成约束——配额本来就该是
  "想画成什么样"的声明，不是"已经画成什么样"的复印件。
- **模板预置 25 种容器类型，但一件容器都不放。** 类型是字典，不是内容；没有字典，调色板里没箱子可放，
  新图等于废的。反之类型放进去了、容器没放，才符合"只铺骨架"。
- **调色板的家具改为"已用类型 ∪ 标准目录"。** 新图零家具时，原来的"按已用类型推导"会得到空列表，
  一件家具都放不出来。现在补一份 11 种标准家具（名字与占地取临海路多数派），已用的排前面、未使用的标 0。

**校验列表为什么要独立成模块**

刷墙时每改一格都会重算校验，而列表是 DOM。整块重建会让滚动位置归零、正在看的条目跳走。
`issues.js` 用"内容签名 + 选中下标"比对，没变就一个节点都不碰；变了也只换 `innerHTML` 并还原 `scrollTop`。

**踩到的坑**

- `.issue[data-cell]` 那套旧写法把"可点"绑在 `data-cell` 上，计数类问题（G11）没格子就点不动。
  改成整行都是 `button`，有格子才定位、没格子只选中并提示。
- 自测里直接调 `history.run()` 改数据不会触发校验（去抖校验挂在 `markEdited` 上）。
  于是把 `validateNow()` 抽出来给脚本用——去抖是刷墙时的手段，脚本要的是确定的时间点。
- 侧栏刷新有 40ms 去抖，点完条目立刻断言 `.issue.on` 必然失败。断言前要等一拍。

### 零点八·补：贴图与旋转（2026-10-29 下午）

用户提的三件事，其实是同一个问题的三个面——**数据里的"占几格 / 朝哪边"和画面上"画什么、画多大"对不上**。

| 问题 | 原因 | 改法 |
| --- | --- | --- |
| 容器是一块带字母的色块 | 容器只按品质上色 + 写字模 | 改画 `crate_*` 箱子贴图，品质缩成右上角一个小方点 |
| 两格家具的图缩在一格里 | 一律用 32×32 基图，塞进 1×2 的框自然只能画满一格高 | 占地 >1 格时改用 `_large` 放大版（32×64 / 64×32），铺满两格 |
| 转视角后家具变成小圆点 | 当初为了规避"旋转后光照错向"，实体在旋转视图里降级成标记 | 改成按「实体朝向 + 视角」换变体，贴图不硬转 |
| 家具不能转，2 格件转不了朝向 | 朝向和占地是两个字段，谁也不管谁 | `R` 一步同时改朝向与占地，检查器只留旋转按钮 |

**为什么用 `_large` 而不是把图拉大**：`_large` 是美术为多格家具单独画的，不是 32×32 的放大版。
把它们等比塞进 2 格宽高比不同的框里，才会有"留白"或"压扁"。选对图之后 `contain` 就够了。

**为什么不让贴图整体转 90°**：所有家具贴图都烘焙了左上光照，硬转会变成光从右上打来。
但屏幕占格在 90°/270° 也在宽高互换，所以"换个朝向变体"和"占格转过来"是对得上的——
用现成的三向美术就能覆盖四个视角，一张图都不用新画。

**新增测试** `tools/test-map-art-map.js`：编辑器读不了目录，"哪些家具有 `_large`、哪些朝向有变体"
只能写死在 `map-art-map.js` 里，这个测试就是那份写死的兜底——声明了必须有文件、有文件也必须声明，
外加容器贴图与 `js/data.js` 的 `CONTAINER_TYPES.art` 逐条比对。

## 零点九、贴图重载（2026-10-29）

画完贴图切回编辑器发现没变，不是编辑器"冷启动"，而是**三层缓存各拦了一道**：

| 层 | 位置 | 何时失效 | 症状 |
| --- | --- | --- | --- |
| 1 | `render.js` 的 `images` Map | 永不 | 会话内怎么刷新画布都是旧图 |
| 2 | 浏览器 HTTP 缓存 | 按 Last-Modified 推新鲜期 | 改完图半小时内按 F5 连请求都不发 |
| 3 | 静态层离屏画布 `staticCanvas` | 只认 `docVersion` | 只有家具变了、地形还是旧的 |

第 2 层的原因是 `python -m http.server` 不发 `Cache-Control`，浏览器退回**启发式缓存**：
新鲜期 ≈ 文件年龄的 10%。一张两小时前改过的图，接下来十几分钟内按 F5 直接被缓存挡掉，
连 304 都不会有——看起来就像"改了没生效"。

**解法**：所有贴图 URL 带一枚版本戳，换戳等于换 URL，缓存键就变了。

- `?v=<毫秒>`——起本地服务时用，query 参与 HTTP 缓存键
- `#v=<毫秒>`——双击直开（`file://`）时用。`?query` 在 `file://` 下会被当成文件名的一部分而 404，
  fragment 不参与资源定位但同样改掉缓存键

**三个入口**

| 入口 | 行为 |
| --- | --- |
| 每次打开页面 | 戳取当前时间，F5 必然拿到最新图 |
| 工具栏「重载贴图」/ `Alt+R` | 会话内改了图不用刷新，清三层缓存重画 |
| 切回窗口时自动探测 | 对已加载的贴图发 `HEAD` 比 `Last-Modified`，有变就整批重载 |

自动探测只比头、不读内容，几十张图在本地是几十毫秒；首次探测只建立基线不触发重载，
否则每次打开都会白重载一遍。`file://` 下没有 HTTP 头可比，探测直接跳过。

**为什么不做文件监听**：浏览器拿不到目录句柄，除非用户每次授权。轮询目录 mtime 又做不到
（`http.server` 不返回目录时间）。切窗口探测是在"零配置"前提下的最优解。

## 零点十、打开任意地图（2026-10-29）

编辑器原来只会 fetch `../linhai-old-quarter/layout.json`，想打开 `design/maps/` 下别的图
只能拖文件。加一个参数：

```
index.html?map=../layout1.json
```

路径相对 `editor/` 算，`rules.json` 从同一目录取，取不到就退回"全不检查"的默认值。
按这个用法验证用户自建的 `layout1.json` 时，暴露出两个既有 bug：

**1. 没有 rules.json 就白屏**

`IO.loadDefault()` 在取不到规则时返回 `{}`，而侧栏与校验器按"完整结构"读
`rules.expect` / `rules.specialChecks`。`Rules.expectations({})` 里
`Object.keys(undefined)` 直接抛错，`apply()` 抛在 `store.set` 之后——
数据其实已经载入，但 `boot()` 的 catch 会把"需要先给一份地图"的遮罩翻出来，
表现为"图明明在，却提示没有图"。

两处一起修：`apply()` 先 `Rules.normalize()` 再进 store；`expectations()`
改成 `Object.keys((rules && rules.expect) || {})`。后者是公共 API，被三处调用，
任何一处忘了归一化都不该让整张图打不开。

**2. 副本之间互相覆盖草稿**

草稿按 `data.id` 存。从临海路另存出来的副本 id 往往还是 `linhai-old-quarter-draft`，
于是两份不同的图共用一个草稿槽，恢复时会串。改成按来源文件名存
（`draftKeyOf = s => s.source || s.data.id`）。

## 零点十一、门与橱窗可编辑（2026-10-29）

门一直只能"看"：悬停面板会列出它，但 `entityAt` 不认识 portal，点不中、删不掉、改不了。
`portals` 里 33 条记录只有文件编辑器能动。

**能做什么**

| 操作 | 入口 | 行为 |
| --- | --- | --- |
| 选中 | 选择工具点任意一格 | 多格门点第二格也能命中 |
| 改名 / 改类型 / 改连接空间 | 检查器 | 每项一步撤销 |
| 删除 | `Delete` / 橡皮 / 检查器按钮 | 摘掉记录 **并把墙补回去** |
| 新开一扇 | 调色板「结构 → 门洞」后点墙 | 两侧空间自动推断 |

**四个判断**

1. **删门必须封墙**。`portals` 和地形是两份真相：只删记录会留下"地形还是 `+`、数据里没有记录"
   的孤儿格。G8 只遍历 `portals`，查不出来，但游戏里那是一道看不见的出入口。反过来也只封
   真正的开口字符（`+` `/` `w`），桥面与阶梯不碰。
2. **门不能拖**。它没有 x/y，只有一组格坐标。拖动要同时决定"旧位置封哪几格、新位置开哪几格"，
   连续手势下每帧重算，很容易画出半截门。第一版只给选中与删除。
3. **开门要求两侧"真的能走"**。第一版只看地形可通行，结果在 (10,8) 开出一扇死门——
   门后两格都站着家具，BFS 一跑立刻报 `G5 孤立可行格`。判据改成"地形可通行 **且** 没有实体"。
4. **connects 用 `spaceAt` 而不是 `regionAt`**。后者只到建筑，同楼两个房间之间的门会写成
   `apartment → apartment`，等于没说。现在优先房间 id，出了房间才退回建筑。

**顺带修的**：检查器的渲染缓存键加了"实体还在不在"。删除是原地改数组、`data` 引用没换，
原先只靠 `kind:id + dataSeq` 判断，删完检查器还停在被删实体的字段上。

## 零点十二、规则分层：硬性 vs 建议（2026-10-29）

**问题**：`layout.json` 换成手工设计之后，构建一直被拦。拦它的不是"图坏了"，而是一整套为
AI 生成版写的验收锚点——`expect.containers: 48`、`minExitsPerBuilding: 2`、
净宽标注、银行安保链、室内绕行……这些在"人手一张一张画"的工作流里反而是噪音：
先摆箱子后开门、临时删掉一扇门、把巷道封起来做院落，都是正常过程。

**决定**：按"会不会坏档"重新分层，不再按"设计得对不对"分层。

| 层 | 判据 | 规则 | 效果 |
| --- | --- | --- | --- |
| 硬性 `error` | 坏了就跑不起来 / 玩家会被卡死 | G1 尺寸与行宽、G2 图例字段、G3 占格重叠与地形冲突、G5（出生点、撤离点可达、**敌人巡逻可达**）、G7 敌人出生与间距、G8 门洞结构、G9 出生撤离点、G10 航点、G11 容器类型未定义、G12 编号唯一 | 拦住构建 |
| 提醒 `warn` | 只是这张图"还能更好" | G2 图例未被使用、G4 分区标注、G5 孤立格 / 房间标注点 / 入口不可达、G6 箱柜操作面、G11 配额与计数 | 只显示，不拦 |
| 关闭 | 为 AI 生成版写的专项验收 | M1–M6 全部（`specialChecks: []`）、`expect` 全 `null` | 整段不跑 |

**为什么敌人那一条必须留在硬性层**：巡逻是"在自己周围随机选点 → 寻路过去"。
出生格若到不了主区域，NPC 只能在原地打转，玩家看到的是"这几个怪坏了"，
那是体验硬伤而不是设计口味。所以 `G5 敌人巡逻不到外面` 保持 `error`，
而它旁边的"孤立可行格"降成 `warn`——玩家进不去只是浪费几格地板。

**恢复办法**：`rules.json` 的 `specialChecks` 加回名字（`buildingEntrances` /
`clearanceWidth` / `bridgeOnlyCrossing` / `bankSecurityChain` / `tideReserve` /
`indoorRouting`），或把 `expect` 里某一项填成数字，那条检查立刻回到
"拦构建"的语义。规则本体没删，只是默认不开——**给 AI 生成版留的门还开着**。

**顺带调整的测试**（不改就会误报）：

1. `tools/test-map-validator.js` 拆成两套规则：`mapRules`（图现在用的，只验基线干净）
   和 `strictRules`（配额按当前数据算 + M1–M6 全开，用来逐条破坏）。规则回归测的是
   "规则开着会不会拦"，与某张图关不关它无关；混在一起会让"图放宽了"看起来像"规则坏了"。
   断言里同时校验级别（`error` / `warn`），防止把降级写成静默丢失。
2. `design/maps/linhai-old-quarter/test.cjs` 只留六个破坏性样例，正向断言收成
   "0 错误 + 3 条路线连通 + 18 条规则在跑"——原来那批"41 个容器""24 敌人"是快照数字，
   图一改就过期。
3. `smoke-test.js` 的"所有容器相邻操作面可达"改成**只报告不失败**。容器被围死是内容问题，
   不是代码通路问题；冒烟测试该盯的是"代码还能不能跑"。
4. `run-test.js` 的"地面贴花可站立"改成按 `propCollisionCells` 逐格判断。原来只查原点格，
   院落树那种"3×3 视觉 + 单格树干碰撞"的写法永远过不了。

**代价**：`node tools/build-linhai-map.js` 现在能过了，意味着**它不再保证图"画得好"**。
质量判断挪到了编辑器的提醒列表里，构建只保证"这图能加载、能跑、能撤离"。

新图落地由 `tools/new-map.js` 一次写三件套（`layout.json` / `rules.json` / `README.md`）。浏览器里"新建"只能下载 `layout.json`——页面写不了目录，这是 `file://` 与 FSA 的硬限制，不要试图绕。

### 2.2 为什么用 UMD 而不是 ESM

`shared/` 要同时被三处消费：浏览器 `<script>`（file:// 双击可用）、既有 CJS 脚本（`require('./validate.cjs')`）、`tools/build-linhai-map.js`（顶层同步调用）。

选 ESM 会逼着 `build-linhai-map.js`、`test.cjs`、`build.cjs` 全部改成 `async main()`，还可能撞 Node 版本对 `require(esm)` 的支持差异。项目没有打包器，UMD 是唯一"零构建、两种环境都能吃"的格式：

```js
(function (root, factory) {
  const api = factory();
  if (typeof module === 'object' && module.exports) module.exports = api;
  else root.MapCore = api;
})(typeof globalThis !== 'undefined' ? globalThis : this, function () { /* ... */ });
```

代价：没有静态 import 的类型提示。可接受——这些文件是数据与规则，不是框架。

同一理由也决定了编辑器脚本用**经典 `<script>` 而不是 ES module**：`file://` 下 `type="module"`
会被同源策略拦掉（origin 为 null），双击直接白屏。代价是各文件用 `window.EditorXxx` 挂载，
换来"双击就能看"这一条体验，值得。

### 2.3 分层边界

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| `shared/map-core` | 字段白名单、默认值、序列化顺序、坐标变换 | 不校验语义、不碰 DOM/fs |
| `shared/map-validator` | 语义校验，产出 issues | 不抛异常、不改数据、不读文件 |
| `editor/*` | 状态、绘制、交互、IO | 不复制校验逻辑，只调 validator |
| `validate.cjs` / `test.cjs` | node 侧壳 | 不重复实现规则 |

一条硬规矩：**编辑器里出现的任何规则文案，必须来自 validator 返回的 issue，不许在 UI 里二次判断**。否则两边迟早不一致。

## 三、数据模型

### 3.1 不变的部分

`layout.json` 保持现有字段结构（schemaVersion 2 起 29 个顶层字段），**不引入嵌套、不改字段名**。理由：`js/data.js` 的编译产物、`render.cjs` 的评审图、`test.cjs` 的 6 条样例全都绑在这套字段上，改结构等于三处重写，收益为零。

### 3.2 新增字段（全部可选，缺省即老行为）

| 字段 | 位置 | 用途 |
| --- | --- | --- |
| `facing` | `props[]` | `front` / `side` / `back`，已有 11 处使用 |
| `mirror` | `props[]` | 布尔，左右翻转（`side` 只有一个方向时的补足） |

| `rules` | 顶层 | `rules.json` 的文件名引用（默认 `rules.json`），便于一图多套规则 |

其余一律不新增。编辑器需要的"视图旋转角度""缩放""当前工具"**属于编辑器状态，不进地图文件**。

### 3.3 `routes` 的归属

`routes` 从 `layout.json` 移除，改为编译期计算：

- `tools/build-linhai-map.js` 调 validator 拿 `result.routes`，写进 `RAID_MAP`
- `build.cjs` 渲染评审图时同样现场算
- `test.cjs` 的 `assert.deepEqual(data.routes, result.routes)` 改为 `assert(result.routes.length === 3)`

好处：单一源，不可能出现"JSON 里的 routes 过期"。

### 3.4 `rules.json`（新增，每图一份）

把 13 项校验里的**本图专属**部分抽出来，通用规则留在代码里：

```json

    "rooms": 24,
    "containers": 48,
    "enemies": 24,
    "exits": 2,
    "bridges": 2,

  },
```

`specialChecks` 是开关列表，每个名字对应 `map-validator.js` 里一个具名函数。新建图不填 `rules.json` 时，这些全部跳过，只跑通用规则。

## 四、校验器改造

### 4.1 从 assert 到 issues

```js
// 现在
assert.equal(data.width, 72, '宽度必须是 72');

// 之后
issues.push({ level:'error', rule:'G1', message:'地图宽度应为 72，当前 84', cells:[] });
```

issue 结构：

```ts
{
  level: 'error' | 'warn',
  rule: string,          // 规则编号，如 G4 / M3
  message: string,       // 中文，可直接显示
  cells?: [number, number][],  // 可定位的格子，点击跳转
  entityId?: string,     // 关联实体，点击选中
  fix?: { label, apply } // 可选一键修复
}
```

`error` 阻断保存到 `design/maps/`；`warn` 只提示（例如"该容器无 preference，将使用容器类型默认值"）。

### 4.2 规则清单

**通用规则 G1–G12**（任何地图都跑）：

| 编号 | 规则 | 依据 |
| --- | --- | --- |
| G1 | 尺寸合法、`rows` 行数字符数一致、图例字符全覆盖、外圈不可走 | 原第 1 项 |
| G2 | 每个图例字符有 `name`/`walkable`/`opaque`/`color` | 新增（防手写漏字段） |
| G3 | 实体不重叠、不压不可走地形、不越界 | 原第 2 项 |

### 4.3 双跑对照（迁移期的验收手段）

M0 阶段保留旧 `validate.cjs` 与新 `map-validator.js` 同时跑临海路：

- 旧：`13 项全绿`
- 新：`issues.filter(level==='error').length === 0`，且 18 条规则逐条命中一次（`warn` 也计数）
- 两者对同一张图必须都无错；若新校验器报错而旧的不报，说明规则搬错了

这条对照跑通后再删旧文件。**不做这一步，拆分必然悄悄改变语义。**

### 4.4 浏览器内运行

`map-validator.js` 无 `fs`、无 `assert`，浏览器直接 `<script>` 引入即可。实测成本：4032 格上跑完 G1–G12 与 6 条 M 规则（含约 30 次 BFS），单次约 8ms。配合 120ms debounce，编辑手感无感。

触发时机：`mouseup`、属性提交、撤销/重做之后——**不在 `mousemove` 里跑**。

### 5.4 视图旋转

用户原话是"物块可以根据目前绘制的视图切换透视方向"。正交俯视没有透视，所以拆成两件事：

**A. 视图旋转（相机，0/90/180/270）**

- 坐标变换：`(x,y) → (y, W-1-x)`（顺时针 90°），绘制时统一走 `map-core.project(x,y,rot,W,H)`
- 网格、坐标标注、方向标、敌人扇形视野、选中框全部随之转
- **贴图不整体旋转**：12 张地块与 60 张道具的资源都烘焙了左上光照，整图转 90° 会让光从右上打来，画面立刻"不对"
- 只有**方向性资源**按旋转族换变体，这就是 `map-art-map.js` 的职责：

| 旋转族 | 变体 | 处理 |
| --- | --- | --- |
| `canal_steps` | `_w` / `_e` | 转 180° 时互换 |
| `bridge_rail` | `_n` / `_s` | 转 180° 时互换 |
| `window` / `door` | `door` / `door_side` | 沿墙走向，转 90° 时换轴 |
| 家具 | 正 / `_side` / `_back` | 按「实体朝向 + 视角」取变体，见 5.4 B |
| 容器 | — | 箱子贴图是方形，屏幕轴对齐，不换 |
| 墙、地面 | — | 屏幕轴对齐，不换 |

- 视图旋转**只用于编辑手感**（画横墙画累了转过来画竖墙），**评审图导出固定 0°**。角标常驻显示当前视角与"N ↑"指北针，避免出图时转错。

**B. 对象朝向（数据，`facing`；占格随朝向一起转）**

- **一个入口**：选中家具按 `R`（或检查器里的「↻ 转 90°」）顺时针转一步。视图旋转退到 `Shift+R`，
  没选中任何东西时 `R` 仍然转视角。
- **多格件**：宽高互换（1×2 ↔ 2×1），朝向在 正 / 侧 之间切换。矩形转 180° 和不转长得一模一样，
  硬切成背面只是白丢细节，所以多格件只有两种长相。
- **单格件**：占格不变，朝向按 正 → 侧 → 背 → 正 循环。
- **容器**：只有一张正面贴图，`R` 直接拒绝并提示，不会顺手把视角转了。
- 转过去放不下（撞墙、压别的实体）就整个不改，弹一句原因——不留半成品状态。
- 摆放时仍自动推导：左右贴墙 → `side`，顶到上墙 → `back`。多格件推导出 `side` 时会顺手把占地也换过来，
  换过去放不下就老老实实摆正面。
- 朝向与占地**不再分开填**。检查器里朝向是只读 + 旋转按钮：两者一旦能各填各的，就能拼出
  "侧面贴图 + 竖着占 1×2" 这种打架的组合。
- 美术缺口：无。14 种家具三向齐全，`tree_courtyard_back` 已补（`tools/test-map-art-map.js` 锁死）。
- 缺变体时退回基名，不静默画错图。

### 5.5 实时校验面板

- 右上角常驻计数 `校验 0 / 3 / 12`，绿/黄/红三态
- 列表按 `error → warn` 排序，每条显示规则编号 + 中文消息
- 点击 issue：视口平移到 `cells[0]`，若带 `entityId` 则同时选中该实体
- 鼠标悬停：画布上该 issue 涉及的格子描红
- `fix` 存在的 issue 右侧给"修复"按钮（如"把该容器移出墙体"→ 找最近可走邻格）

### 5.6 性能

- 分层离屏 canvas：`ground` / `structure` / `entities` / `overlay` 四张，只有脏层重绘
- 地形变更只重绘所在矩形区域（`ctx.clearRect` + 局部重画）
- 实体拖动时用 `overlay` 层画预览，松手才提交到 `entities` 层

## 六、新建地图流程

> 本节是 M3 的实现说明（2026-10-29 落地）。生成器在 `shared/map-templates.js`，界面在 `editor/newmap.js`，
> 落盘在 `tools/new-map.js`，回归在 `tools/test-map-templates.js`。

### 6.1 尺寸

| 预设 | 用途 | 约束 |
| --- | --- | --- |
| 48×36 | 单栋小图（诊所、公寓） | 四周 1 格边界 |
| 64×48 | 双岸街区（临海路缩小版） | 同上 |
| 72×56 | 与临海路同尺寸 | 同上 |
| 自定义 | 24–128 宽高 | 宽高独立，**不四舍五入**：48.5 直接拒掉 |

尺寸只影响 `width`/`height`/`rows`，其余字段结构与 72×56 完全一致。**校验器的通用规则必须对所有尺寸成立**——这是 M0 拆分质量的真检验。回归里跑了 24×24 到 128×128 的 15 组，全部 0 错误 0 提醒。

### 6.2 模板

| 模板 | 生成内容 |
| --- | --- |
| 空白 | 全 `.` + 外圈 `#`，出生点在正中偏北，两个撤离点在南边两角 |
| 双岸运河 | 中央 6 列 `~`、两座 2 格宽 `=` 横跨全河、两岸 `r`、最多三处 8×8 `q` 院落 |
| 单栋建筑 | 街道中央一栋 24×16 的房：2 格走廊 + 四间房 + 四道内门 + 南门 + 东侧门 |

三处与初版方案的出入：

- **院落不是随机的。** 随机会让同一份 spec 生成两张不同的图，回归没法逐字节比对。改为按槽位固定摆放，放不下就少放一个（小图不硬挤）。
- **单栋建筑多了一层：房间与门洞。** 只铺地形的话，`rooms`/`portals` 是空的，G5 没得检，用户还得手填一圈。现在直接给出五个 room（含走廊）+ 六个 portal（四内门 + 南门 + 侧门），并写明 `connects`。
- **走廊登记成 room。** 它需要锚点、需要被 `connects` 引用，而 schema 里没有"走廊"这种类型；当成 room 处理最省事，也与临海路的 `apartment.hall` 一致。

模板只铺地形与骨架，不生成容器/敌人/家具（那些是设计决策，不该自动填）；但**容器类型字典要带上**，否则调色板里没箱子可放。

### 6.3 新图落地

```
design/maps/<id>/
├── layout.json     status: "draft"
├── rules.json      expect 全为 null，specialChecks 为空
└── README.md       坐标约定、图例、模板做了什么 / 没做什么、验收清单占位
```

`expect` 为 `null` 时，M1–M6 全部跳过，只跑 G1–G12；侧栏显示"本图规则未设定"。等设计定稿再填 `expect`，此时 M 规则才生效——**避免新图一建就红一片**。

`quotas` 同理取 `null` 而不是 `0`：`0` 会让"放下第一个箱子"立刻触发 G11。点一次"同步配额"之后它才变成真约束。

命令：

```bash
# 浏览器里"新建"只能下载 layout.json（页面写不了目录）
node tools/new-map.js --id clinic-draft --size 48x36 --template building --title "临海路诊所"
# 目录已存在时会拒绝，确认覆盖加 --force
```

脚本末尾会顺手跑一次校验；有错误或提醒就以非零码退出，不把脏图写进 `design/maps/`。

## 七、文件读写

### 7.1 主路径：File System Access API

- `showOpenFilePicker` / `showSaveFilePicker`，句柄存 IndexedDB（键 `map-editor:handle:<id>`）
- 打开过一次后，"保存"直接写回，无对话框
- 仅 Chromium 支持；`file://` 下多数版本可用，但**推荐起本地静态服务**（`python -m http.server`），避免个别版本对 `file://` 的限制

### 7.2 降级：导出 + 采用

不支持 FSA 时：

1. "保存"→ 下载 `<id>.json` 到下载目录
2. 页面给出可直接复制的命令：`node tools/map-adopt.js ~/Downloads/linhai-old-quarter.json`
3. `map-adopt.js` 校验 `id` 与目标目录一致、跑 validator、无 error 才落盘

### 7.3 自动保存与恢复

- 每 2 秒把文档写进 `localStorage['map-editor:draft:<id>']`（含时间戳与 sha）
- 打开时若发现 draft 比磁盘文件新，弹出"检测到未保存的修改，恢复 / 丢弃"
- 关闭页面前 `beforeunload` 若有未保存改动则拦截

### 7.4 保存前的闸门

- `error` 存在 → 禁止写入 `design/maps/`，只能"另存为草稿"到下载目录
- `warn` 存在 → 允许保存，但弹确认框列出 warn 条数
