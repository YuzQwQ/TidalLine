# 物资刷新点

地图字段lootSpawns为独立数组，每条含id、name、x、y、pool、chance（出现概率0–100）、weights（白绿蓝紫金红六档百分比，合计100）、offsetY（绘制上下偏移，-32至32像素）。不写入地形字符，不占碰撞。可以与家具重叠，编辑器绘制和选择优先级置顶；右侧图层列表可以独立隐藏。

刷新类型含全部收集品、各收集品类别、治疗药物、弹药、枪械、配件、头盔、护甲、背包。先按出现概率决定是否出货，再按六档概率抽一件；弹药是一组。缺少物品的品质不参与抽取，剩余可用档位重新归一；如果所有非零权重均为空档，则不生成。钥匙及仅专属池产出的物品不进入此池。

每次开局生成一次，拾取后本局不补货。复用测试场认可的尺寸与品质描边；家具仍保留原有碰撞和遮挡，物品可以从附近拾取。装备沿用现有穿戴／收进背包流程。

在编辑器左侧最上方选择“物资刷新点”，点地板或家具放置，再到右侧填写配置。保存layout后运行node tools/build-linhai-map.js编译，node build.js --assets-only同步离线版。本批不自动替地图新增点位。

## 出货预案

编辑器右侧「出货预案」下拉提供五档梯度，一键填入六档权重**与出现率**（`chance`），二者一起写入。新建点的默认出现率也从 100% 降到 70%。逐档改权重会显示「自定义」，改出现率不影响权重预案，两个值都能单独覆写。数值为 `all` 池实测单点期望。

`chance` 在**每次开局对每个点独立判定一次**（`GroundSpawns.generate`）：设 30% 的珍藏点大约每三局才出现一次，全图散落物数量每局也会自然波动，而不是每局固定刷满整张图。已经放好的旧点不会自动改值，重新选一次预案即可。

**缺档修正**：`js/loot-spawn-data.js` 的 `coverage` 记录各池六档是否真有物品。收集品族（`all` 与九类）六档齐全；`medical / ammo / gun / helmet / body / bag` 无红档，`attachment` 只有绿蓝紫。落在空档的权重会重归一到可用档；若所有非零权重都是空档，检查器提示「不会生成任何物品」，运行时该点不生成。装备池价值下限高（枪械白档均价 ¥3.3 万），密度靠 `chance` 控制而不是压低稀有度。

**预算**：整图期望建议控制在 **¥40–60 万/局**（满图约 ¥500 万的 8–12%，与钥匙池 +¥38.4 万同量级）。60 点示例配比 S0×40 / S1×12 / S2×5 / S3×2 / S4×1，配合预案出现率 ≈ ¥428,160/局、平均每局出 43 个点、红档约 1/27 局一件；**若所有点都设 100%，同样配比会到 ¥699,375/局**（高出 63%），且每局固定刷满 60 个点，地图观感不再变化。默认权重 `[10,18,32,30,9.5,.5]` 单点 ¥62,144，密集布点会超预算，应改选预案。

`coverage` 由运行时 `GroundSpawns.candidates` 统计，`node tools/test-loot-spawns.js` 会校验两侧同步；物品表变更后测试会失败，按提示更新 `coverage`。

回归：node tools/test-loot-spawns.js。
