# 仓库页面改良

参考temp files/仓库页面参考.png的三栏结构与材质，文字、分类和数值以项目为准。

- 左侧：全部、武器（枪械与近战）、弹药、防护装备、背包、医疗物品、收集品；收集品可展开现有九类。计数统一为占用格数，避免把90发弹药说成90格。
- 中间：真实600格容量与占用条、搜索、品质筛选、排序／整理视图、库存网格与分页。整理仅改变展示顺序，不合并或丢弃物品，不保存虚构位置。
- 右侧：选中物品的图、品质、类别、堆叠、重量、耐久／弹匣／药物剩余容量等真实属性，完整说明与可用动作；动作区固定，内容滚动。
- 使用、入包、出售、退弹、前往备战接现有规则。绑定赠刀不可售，背包满／超重失败不损失物品；治疗与堆叠采用当前定义，不复用参考图的数值。
- 批量操作本轮仅提供“出售寻常收集品”，增加金额与数量确认，排除医疗、弹药、装备。锁定、维修、多选批处理为规划入口，点击明确提示未开放。
- 新模块js/storage-ui.js负责布局和选择，js/storage-config.js负责分类与规划状态，assets/ui/storage.css负责视觉。Base新增可覆写的库存列表查询点，在搜索排序后再分页；原交易与存档逻辑保留。
- 仅仓库页移入原仓库DOM，返回备战或商人时由已有节点管理归还。独立演示使用静态标记，不连接Save或localStorage。无新地图素材或持续动画。
- 开发与离线版覆盖1440×900、1280×720和窄屏；验证跨页搜索、分类、排序、药物剩余容量、操作失败无损、批量确认、绑定与节点归还。沿用地图快照同步单文件。
