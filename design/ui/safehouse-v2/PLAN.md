# 局外 UI v2：完整产品结构与分阶段接入

## 1. 差距分析

v1将实际功能边界误作视觉边界：房间是几何线框，右栏只有出行检查，缺少底部情报区；备战占据全局导航，主操作没有形成参考图的红／金层级。设施、未来任务与档案没有稳定容器，后续扩展会不断改版。

v2保留参考图的构图和信息密度：顶部全局导航；中央大幅藏身处场景；右侧据点概览；底部角色、事务、广播三卡；右下红色备战、金色出发。使用有像素笔触的环境插画与金属面板衔接现有游戏，不将参考图中的3D风格直接移植。

## 2. 组件与能力分层

|组件|现有能力|未来预留|纯视觉|
|---|---|---|---|
|全局导航|藏身处、商人、仓库、地图、图鉴档案|任务页、身份成长|图标、金属底板、选中反馈|
|玩家摘要|信用点、本地撤离者身份|自定义姓名、等级、更多货币|头像徽章|

|据点概览|实际仓库占格、现有护甲耐久摘要、实际HP|维护服务、伤势恢复、制造队列|波形、细边框|
|底部状态|实际HP|伤势与恢复状态|生命图标|
|待处理事务|当前提示无已开放任务|任务、委托、奖励|静态演示卡，仅独立设计稿|

未开放入口都可以点击查看明确说明，不能无反应。运行游戏使用真实值；未实现的维护、制造、伤势、任务均标未开放，不写假进度。独立原型可以展示带“演示”标签的设施等级与进度。设施升级不影响当前货架或存档。

## 3. 架构

`js/safehouse-config.js`：导航、设施、广播和能力状态，稳定ID；未来可配置开放或替换目标。

`js/safehouse.js`：独立Safehouse视图控制器，负责场景、概览、状态卡、广播、功能说明；通过适配器读取已有Save/Base/MapSelect。独立原型使用demo适配器，不加载游戏脚本、不读写localStorage。

`assets/ui/safehouse.css`：统一壳层、金属组件、响应式及工作页样式。当前装备、库存、交易确认继续使用原业务，不复制一套买卖逻辑。图鉴档案读取已有收集记录，任务页暂作预告。

`assets/ui/safehouse/room.webp`：静态像素环境插画，完整背景、无烘焙文字；原稿与提示词保存在本批次sources，不登记为地图摆件。商人立绘用已有三图，离线打包仅加入实际使用的UI资源。

## 4. 布局与交互

1440×900主尺寸，1280×720紧凑模式。全局导航64–76px。总览场景是全屏底图，视觉中心在左侧约75%，右侧280–330px据点面板，底部三张状态卡与行动按钮对齐。场景入口使用归一化坐标，扩展设施有明确规划标记。备战不进入顶部主导航。

商人工作页保留左侧货架、右侧仓库，中间可显示人物职业卡；备战保留装备与背包，右侧仓库。仓库页扩大库存区。保留所有原物品操作、近战槽、剩余药品容量、装卸弹与交易确认。

小于800px时导航横向可滚动，场景入口变为按钮网格；概览、三张状态卡顺序排列；底部双按钮有独立占位，不遮挡内容。工作页改为单列滚动，原仓库格子仍按实际空间计算。关闭说明／档案支持Esc和关闭按钮。

广播只在藏身处总览可见且页面可见时以10秒周期轮播；暂停按钮与手动前后切换。离开总览、进入地图、进入游戏、切后台时清除计时器；不创建RAF，不添加环境粒子循环。减少动态效果偏好默认暂停轮播。背景静态、纹理静态，禁用高成本持续模糊。

## 5. 接入边界与验证

先发布共享模块独立原型，再挂载游戏原藏身处DOM：不重写Save与交易，不伪造已完成任务，不提前加入制造或信任逻辑。离线构建内联CSS、共享脚本与UI图片，使用`--assets-only`保留当前地图快照。

记录实施前回归：`node run-test.js`为300通过、0失败。接入后验证总览、全部导航、未开放说明、三商人买卖、收费治疗、备战转移、地图返回、档案真实记录、广播单计时器生命周期；开发与离线版分别检查1440×900、1280×720和390×844。读写范围只通过原交易与原存档接口；UI视图切换和广播不保存新游戏状态。
