# 《潮汐线》新增商人部署方案 v1.0

**项目：** TidalLine  
**新增商人：** 维克托·萨伦（Viktor Saren）  
**商店类型：** 贸易商  
**开发阶段：** 第一阶段，商店及UI接入  
**实施原则：** 复用现有系统，控制改动范围，不提前实现未确定的功能。

---

## 一、开发目标

在现有玛拉·维恩、埃德加·洛克、林岑三位商人的基础上，新增第四位商人：维克托·萨伦。

要求：

1. 在商人总览页面增加维克托的入口。
2. 为其创建独立商店页面。
3. 实现白色至紫色部分收集品的购买功能。
4. 复用现有的货币、库存、购买结算与物品数据。
5. 接入角色立绘、人物简介和交互台词。
6. 保留现有商人系统的设计风格及功能。
7. 暂不实现动态物价、收购业务和以物易物。

**不要为了新增商人而重构整个交易系统。**

### 人物背景

维克托·萨伦是一位成功的连锁超商企业家。

他的企业拥有大量零售门店、仓储设施和物流渠道，与众多企业家、供应商、政府采购人员保持合作。

尽管已经积累了庞大财富，他依然喜欢亲自巡视门店、接待顾客、检查商品和洽谈交易。

他性格外向、健谈，擅长迅速拉近与陌生人的距离。

维克托并非单纯贪财。他真正享受的是发现商机、组织商品流通、满足市场需求，以及促成一笔漂亮交易的过程。

环礁湾灾变后，他利用原有商业网络建立了封锁区外围的物资交易渠道。

对普通拾荒者而言，他是一位热情亲切的商店老板。

但在商业圈与上层社会中，他拥有远比外表所暗示的更强大的影响力。

### 性格表现要求

- 经常面带笑容，讲话热情。
- 喜欢主动推销商品。
- 与新顾客也能表现得十分熟络。
- 对商品、价格和市场需求有敏锐判断。
- 可以慷慨，也会精打细算。
- 不要塑造成贪婪、阴险的刻板奸商。
- 不要塑造成愚蠢的喜剧角色。
- 严肃时可以展现企业家的沉稳与决断力。

### 立绘生成提示词

绘制游戏《潮汐线》的一名男性NPC商人，维克托·萨伦，52岁，是大型连锁超商集团的创始人与老板。

人物是一位体格略壮实、精力充沛的中年大叔，拥有干练整齐的短发、修剪精致的小胡子、圆熟亲切的面容和充满感染力的笑容。

他身穿奶油白色长袖衬衫，袖口略微卷起，佩戴醒目的红色领结，穿深棕色或深灰蓝色高腰背带裤，背带具有传统金属扣件。服饰整洁、考究，但不显得奢华。

人物神态热情、自信，像一位亲自出现在自己超市宣传广告中的招牌老板。一只手可以拿着商品目录或账簿，另一只手自然地做出欢迎顾客的姿势。

背景是一间复古超商办公室或商品陈列室，隐约可见货架、包装商品、纸箱、老式收银设备及商业海报。

采用传统厚涂油画风格，明显的手绘笔触，温暖的赭黄、灰褐、米白色调，红色领结作为视觉焦点。柔和的室内灯光，成熟自然的人物比例，具有浓厚的年代感。

4:5竖幅构图，适合游戏NPC商人立绘。

避免现代商务精英西装、夸张的卡通比例、过度肥胖、邪恶奸笑、赛博朋克元素、照片质感、文字水印。

## 五、商店经营范围

### 1. 基本定位

维克托是综合性的商品贸易经营者，但目前只出售部分收集品。

玩家从他这里购买的物品进入现有仓库系统。

这些物品与地图搜刮获得的对应物品完全一致，不额外创建特殊版本。

### 2. 商品稀有度

允许出售：

- 寻常（白）
- 良品（绿）
- 上乘（蓝）
- 稀见（紫）

不出售：

- 珍罕（金）
- 孤品（红）

严格沿用项目当前稀有度定义，不要新增稀有度或改变物品品质。

### 3. 商品类别

建议优先选择：

| 类别 | 是否出售 | 说明 |
|---|---|---|
| 生活用品 `life` | 是 | 主要经营类别 |
| 电子产品 `elec` | 是 | 主要经营类别 |
| 工业器材 `ind` | 是 | 主要经营类别 |
| 文物藏品 `collect` | 少量 | 只选适合公开流通的普通藏品 |
| 医疗收集品 `med` | 少量 | 排除危险样本与高度专业的特殊物品 |
| 情报资料 `intel` | 暂不出售 | 保留其调查与秘密性质 |
| 军事物资 `mil` | 暂不出售 | 由其他专门渠道经营 |
| 神秘学物品 `occult` | 暂不出售 | 与隐秘世界的稀缺性保持一致 |

类别划分为商品筛选依据，不代表该类别所有物品都应自动上架。

### 4. 商品筛选规则

建议设置独立的商人商品白名单。

例如：

`merchant_inventory.viktor`

从现有物品数据中引用商品ID，不复制或重新定义物品。

初版建议上架约12—20种收集品，覆盖不同稀有度和经营类别。

优先挑选符合普通商业渠道流通逻辑的商品：

- 民用生活用品。
- 常规家用电子产品。
- 工业生产相关零件。
- 少量普通收藏品。
- 少量可以合法流通的医疗设备收藏品。

不要自动加入整个类别。

### 5. 价格规则

**第一阶段不引入动态行情。**

- 使用现有物品参考价值和项目当前商店定价规则。
- 维克托出售收集品的价格保持固定。
- 如当前系统没有对应的商店售价，可以设置独立的静态出售倍率。
- 不允许玩家以低于商人回收价的价格直接购入并立即出售套利。
- 不改变其他商人的商品售价或现有经济参数。
- 后续动态物价系统单独设计与实施。

### 6. 商品库存

优先复用现有商店的库存机制。

若当前商店没有数量限制，第一版可以暂时保持相同逻辑。

但数据结构应允许后续扩展：

- 商品库存数量。
- 商品限购数量。
- 商品上架条件。
- 信任等级要求。
- 动态价格系数。

这些字段可以预留，**但本次不需要实现对应玩法**。

## 六、商店页面设计

### 页面整体结构

维克托商店沿用现有商店页面的布局框架。

建议区域：

**顶部区域**
- 返回商人总览。
- 商人姓名。
- 商店类别。
- 玩家当前现金。

**人物展示区域**
- 维克托立绘。
- 简短人物介绍。
- 当前交互台词。

**商品区域**
- 商品列表。
- 商品图标。
- 名称、稀有度、售价。
- 持有数量。
- 购买按钮及结算逻辑。

**商品详情区域**
- 选中商品的信息。
- 原有收集品描述。
- 商品价格。
- 当前仓库持有数量。

### 商品分类

可沿用现有收集品分类。

建议提供以下过滤选项：

- 全部商品
- 生活用品
- 电子产品
- 工业器材
- 文物藏品
- 医疗收集品

只展示当前确实有在售商品的分类。

### UI设计原则

1. 保持与玛拉、埃德加、林岑商店一致的布局语言。
2. 商品展示复用现有物品组件。
3. 稀有度颜色及边框沿用当前设计。
4. 角色立绘应充分展示红领结和背带裤等特征。
5. 不要为维克托单独开发一套完全不同的商店交互。
6. 不增加当前阶段不需要的图表、行情曲线、兑换面板等组件。

## 八、数据与代码接入

请先检查项目当前商人系统的实际结构，再选择最少侵入的实现方式。

建议商人数据包含：

- `id`
- `name`
- `role`
- `description`
- `portrait`
- `inventory`
- `dialogues`

其中商品数据应引用当前已有的物品ID。

### 核心要求

1. 复用现有商人组件。
2. 不为维克托硬编码独立的购买逻辑。
3. 尽可能采用数据驱动方式新增商人。
4. 商品ID、名称、稀有度、描述从原有物品数据读取。
5. 购买结算必须复用现有货币扣除与仓库入库逻辑。
6. 原有三位商人的购买、治疗、枪械改装等业务必须保持正常。
7. 不修改已有收集品的稀有度和基础价值。
8. 保留后续增加商人信任、兑换、动态物价的扩展能力。

## 十、实施步骤

### 阶段一：检查现有结构

检查：

- 商人总览页面。
- 商人详细页面。
- 商人配置数据。
- 物品数据来源。
- 商品购买逻辑。
- 立绘资源路径。
- 台词触发机制。

在此基础上确认最小修改范围。

### 阶段二：角色接入

- 新增维克托商人配置。
- 配置人物姓名、简介和立绘。
- 加入商人总览。
- 调整总览布局，使四位商人正常显示。

### 阶段三：商店接入

- 建立独立商品白名单。
- 从现有收集品中筛选白至紫稀有度商品。
- 配置商品售价。
- 接入商品购买与仓库入库。
- 检查库存、现金不足等边界情况。

### 阶段四：台词接入

- 新增总览代表台词。
- 接入三条随机问候。
- 接入两条闲置台词。
- 接入两条购买成功台词。
- 保留未来扩展台词。

### 阶段五：界面统一与测试

检查：

- 四位商人的布局是否一致。
- 所有立绘是否正确缩放和裁切。
- 商品稀有度是否正确。
- 商品售价是否正确。
- 仓库入库是否正常。
- 原有三位商人功能是否受影响。
- 不同窗口尺寸下的UI是否正常。

- [ ] 购买后商品正确进入仓库。
- [ ] 问候、闲置及购买台词按预期触发。

- [ ] 没有提前加入动态价格、兑换或收购功能。

## 十二、后续扩展方向

维克托的长期定位是《潮汐线》的收集品交易中心。

未来可逐步增加：

1. 从玩家手中收购不同类别的收集品。
2. 根据市场行情调整商品售价和回收价。
3. 玩家低价购入、跨周期高价出售的交易策略。
4. 有限库存和有限高价收购额度。
5. 商人信任等级与供货渠道解锁。
6. 特殊收集品采购委托。
7. 与其他专业商人的以物易物配方相互联动。

**当前版本的首要任务，是把维克托作为一位有完整角色形象、商品货架和交互台词的正式商人接入游戏。**

不应以未来系统尚未实现为理由，阻碍当前商店的正常上线。
