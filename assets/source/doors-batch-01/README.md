# 特殊门与门洞墙顶

后续修正：侧向素材已由`../doors-batch-02/`的32×32俯视图替换；本批次原稿和预览保留作历史记录，当前侧门来源以新批次manifest为准。

横墙正面素材随后由`../doors-batch-03/`的格内覆盖层替换，当前成品来源以第三批manifest为准。

新增单向受阻木门、上锁铁门，正面及侧面分别由内置image_gen生成；原稿保存在sources/，提示词为`assets/source/prompts/special-doors-v1.json`。成品为`assets/props/door_barricade.png`、`door_barricade_side.png`、`door_locked.png`、`door_locked_side.png`，32×48、16色透明PNG。已登记scene-component，占地1格；侧面使用variantOf+facing，不作为家具重复放置。

所有普通门、强化门与新门均在门体上方叠加相邻墙体的墙顶半格，沿用同一贴图与格坐标，横墙、竖墙及双格门共享；只补视觉，不改变门洞碰撞或通路。编辑器亦显示墙顶及新门类型。

编辑器选中门洞后：

- `门体类型`：normal普通、barricade单向受阻、locked上锁铁门。
- `允许踹开侧`：横墙北/南，竖墙西/东。受阻侧不进入可交互候选表；正常侧提示“踹开”，踹开后移除本局限制，双方都可开关。受阻面绘制木闩，正常面绘制普通门。
- `对应钥匙ID`：与玩家背包或安全箱里物品的id或doorKey严格匹配。没有钥匙/钥匙不符均拒绝开锁；钥匙不消耗，本局解锁后自由开关。未配置keyId会校验报错，不会静默变成普通门。
- 新门字段通过JSON序列化和编译器保留；普通旧门仍沿用原开局状态，特殊门开局关闭，每局重置。

钥匙物品的正式定义和获取渠道后续设计；判定接口已就绪，测试钥匙只在测试场景内生成，不加入正式掉落、商人、物品总表或存档。测试页使用靶场的存档隔离。

开发测试：打开根目录`doors.html`或`index.html#doors-test`；离线版也可用`潮汐线.html#doors-test`。北侧/西侧测试单向门，按钮领取正确或错误钥匙，按E交互；“重置门”恢复初始状态。未改动正式地图摆门点位。
